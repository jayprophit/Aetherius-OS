# Release Gate

**Verdict today: `NOT_RELEASABLE` by design.**

The gate is fail-closed. It checks evidence, not intentions:

```sh
node scripts/release-gate.mjs
```

Exit code `0` means every blocker passed. Any non-zero exit means the product is
not publicly releasable.

## What must be true

| Gate | Evidence |
|---|---|
| Release scope approved | `release/release-scope.json` has `status: APPROVED`, a real semver, platforms, and an in-release list |
| Package metadata | `package.json` is not `0.0.0`, `private` is `false` |
| Legal | Real `LICENSE`, `SECURITY.md` with a monitored contact, reviewed privacy policy, generated third-party notices |
| SBOM | `release/evidence/sbom.cdx.json` is CycloneDX with components |
| Signed artifacts | Every artifact in `release/artifacts/` has `.sig`, `.asc`, `.p7s`, or `.minisig` |
| Security | Independent penetration test, named auditor, `status: PASS` |
| Accessibility | Independent WCAG 2.2 AA audit, named auditor, `status: PASS` |
| Installation | Every declared platform has `install: PASS` and `launch: PASS` |
| Rollback | Real upgrade-and-rollback exercise with data preserved |
| Performance | Measured p95 and hardware details |
| Fixtures | Full acceptance fixtures, not structural-only |
| Benchmark | Every dimension measured 5/5, weighted score 100 |
| Kernel honesty | No false ternary-hardware, quantum-hardware, or bootable-OS claims |
| Self-host stack | Compose template present |

## Evidence locations

Release evidence is kept outside `dist/` so `vite build` cannot delete it:

```sh
node scripts/release-sbom.mjs
RELEASE_GATE_OUT=release/evidence/gate-report.json node scripts/release-gate.mjs
```

- `release/evidence/` — SBOM, gate report, PWA report, and rollback report.
- `release/artifacts/` — final signed artifacts and detached signatures.
- `docs/evidence/` — generated install, performance, and rollback evidence,
  plus the independent-audit templates that remain `NOT_PERFORMED`.

## Templates and generated evidence

`docs/evidence/security-audit.json` and
`docs/evidence/accessibility-audit.json` remain templates with `NOT_PERFORMED`
values. Do not change them to `PASS` without an independent auditor.

The install, performance, and rollback files are generated by real commands and
must be regenerated, not hand-edited:

```sh
npm run verify:pwa       # build + installability/launch + loopback performance
npm run verify:rollback  # two builds, upgrade, rollback, browser-storage check
```

The approved scope in `release/release-scope.json` is a real owner decision,
recorded in `release/OWNER-APPROVAL-2026-11-03.md`; it does not make the gate
green. A green gate that lies is worse than a red gate that is honest. The gate
rejects empty or placeholder LICENSE/SECURITY/privacy files.

## How to turn it green

1. Owner supplies the legal entity, monitored security contact, and a
   lawyer-reviewed privacy policy.
2. Sign the web/PWA bundle and every native artifact; generate the SBOM.
3. Book independent security and accessibility audits.
4. Run install/launch/rollback on every remaining native platform; keep the
   web/PWA evidence current.
5. Run full acceptance fixtures and the 5-star benchmark.
6. Fill evidence files with real results and attach logs/screenshots.
7. Run the gate; fix every blocker until exit 0.
